Universal NLA · Activation Oracle · v24

One trained trunk reads bias, direction, and deception
from any LLM's activations — architectures it has never seen included.

A single Qwen3-1.7B + LoRA trunk, paired with a small per-architecture linear adapter, answers calibrated "does this activation exhibit behaviour X?" questions across a pool of structurally different models. Adding a brand-new architecture is a closed-form linear fit — not a retrain. This page documents v24: a multilingual-Wikipedia AV corpus + direction-aware hard-negative training that beats the previous flagship (v22) on every measured axis.

Architecture

Every model M in the pool gets its own tiny linear enc_M / dec_M pair projecting into a shared 2048-d space — the same space the Qwen3-1.7B trunk was tuned to read. The trunk itself never changes per architecture.

Results

Mean AUROC across 12 genuinely held-out architectures never seen during AV training — LFM2.5-ColBERT-350M, Ministral-8B, Mistral-7B-v0.2, OLMo-1B/2-1B/2-7B, Qwen1.5-7B, Qwen2.5-Coder-7B, Qwen2.5-1.5B, Llama-3.2-1B, QVikhr-3-1.7B, SmolLM2-1.7B.

What moved the number: a 50,000-passage AV verbalization corpus (multilingual Wikipedia, no code — a code-ablation counterfactual showed code specifically hurts cross-architecture direction/deception transfer), a 16-architecture AV pool (vs. v22's narrow 5-tag subset), and direction-aware hard-negative training (biased ↔ balanced same-topic pairs via --dir-pairs-dir) which closed an initial direction-detection deficit into a clean win.

Bonus finding — concept-swap probe

A small exploratory replication of a verbal-report / activation-patching experiment, run on both an in-pool trunk (Qwen3-1.7B) and a genuinely held-out target (Llama-3-8B, read via a closed-form add_held_out_tag encoder):

  • The oracle's open-ended verbalization of a patched activation is most accurate near the layer the encoder was originally calibrated at (depth ≈ 0.5 of the target model).
  • Causal behavioral control over the target model's own continuation only kicks in at later layers (depth 0.7–0.9) — a concept is legible to the oracle before it becomes load-bearing for the target model's own output.
  • The pattern held on the held-out architecture too, despite its encoder having zero gradient steps — evidence the shared space itself, not per-model fine-tuning, carries the signal.

Code

Three entry points cover the whole v24 pipeline: extend the corpus, train, and read a new architecture zero-shot.

scripts/audit/build_wikicode_corpus.py — view on GitHub
# 50k passages: 30% en-wiki / 30% code / 40% multilingual wiki
python scripts/audit/build_wikicode_corpus.py \
  --out-dir artifacts/wikicode_v24/exp2_50k \
  --n-passages 50000 \
  --en-frac 0.3 --code-frac 0.3 \
  --other-langs ru,zh,ja,de,es
scripts/audit/train_v18.py — view on GitHub
# detect + AV + direction hard-neg, joint SFT
python scripts/audit/train_v18.py \
  --trunk Qwen/Qwen3-1.7B --lora-r 32 \
  --mix 6:2:0:2 # detect:av:lie:latentqa \
  --detect-mix 2:1.5:1.5:1:1 \
  --dir-pairs-dir /big/audit/v22_dir \
  --av-pool-dir artifacts/wikicode_v24/exp2_50k \
  --out artifacts/wikicode_v24/exp2_50k_dirfix
nla/enc_dec_adapters.py — view on GitHub — reading a brand-new architecture, zero training
from nla.enc_dec_adapters import ModelPoolAdapters

adapters = ModelPoolAdapters.load("artifacts/wikicode_v24/exp2_50k_dirfix/adapters")

# a few hundred mean-pooled activations from a model NEVER in the AV pool
adapters.add_held_out_tag(tag="my-new-model", h_new_raw=pooled_activations)

# read it immediately — closed-form lstsq solve against the post-SFT serve cache,
# no LoRA update, no gradient step
proj = adapters.encode("my-new-model", h_vec)

Architecture pool

16 architectures in the AV training pool; results above are measured on 12 different, genuinely held-out ones.

Trained (16)

Bloom-560M, Gemma-2-9B, GPT-Neo-1.3B, GPT-2-Medium, LFM2-1.2B, Phi-1.5, Pythia-410M, Qwen2.5-{0.5B, 7B}, Qwen3-{0.6B, 1.7B, 4B}, SmolLM2-360M, SmolLM3-3B, Vikhr-7B, YandexGPT-5-Lite-8B.

Held-out (12, evaluated only)

LFM2.5-ColBERT-350M, Ministral-8B, Mistral-7B-v0.2, OLMo-1B, OLMo-2-1B, OLMo-2-7B, Qwen1.5-7B, Qwen2.5-Coder-7B, Qwen2.5-1.5B, Llama-3.2-1B, QVikhr-3-1.7B, SmolLM2-1.7B.
