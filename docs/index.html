Universal NLA · cross-architecture activation reader

One architecture to read them all.

A Qwen3 trunk under 2B parameters reads bias, direction, and deception straight out of the activations of models up to 8B — 4-5× its own size — including architectures it has never seen.

That trunk — a lightly fine-tuned Qwen3-1.7B, paired with a small per-architecture translator — answers calibrated "does this exhibit behaviour X?" questions across a pool of structurally different models. Adding a brand-new architecture is simple math, not a retrain. Trained on a 50,000-passage multilingual-Wikipedia corpus with direction-aware hard-negative training, evaluated on 12 architectures it never saw during training — spanning 350M to 8B parameters across six different model families.

Where this idea comes from

Two pieces of prior work, and one observation about how LLMs are trained, are what this project is actually built out of.

Natural Language Autoencoders

Anthropic's approach: take a big model, take its own internal activations, and train a second copy of that same model to describe those activations in plain English — well enough that a third piece can rebuild the original activation from the description alone. In effect, teaching a model to translate its own internal states into language a human can read.

Activation Oracles

A different, narrower question: rather than describing everything about an activation, train a reader to answer a specific question about it — is the model about to say something harmful, biased, or false, before it actually says it? Supervised, calibrated, and (in the work this is named after) tested on questions and contexts far outside what it was trained on.

Both of those were built and evaluated per model — one autoencoder, or one oracle, per specific model you want to read. The observation that motivates this project: most LLMs are trained on a heavily overlapping slice of the internet — Wikipedia, Common Crawl, similar code corpora. Independently trained models tend to converge on similar internal representations for the same underlying concepts, even with completely different architectures and parameter counts. If that's true, a single reader — not necessarily a huge one — should be able to interpret many different models' internals, as long as each model's own activation space gets mapped into a common one first.

The recipe here is Anthropic's Natural Language Autoencoder training approach, applied across architectures instead of within one: train on activations from many different models at once, normalizing each model's activation dimensions into the same shared size before the reader ever sees them, so every architecture presents the reader with the same shape of input.

What this actually does

When any LLM answers you, its internal activations — the numbers flowing between layers — already encode things the text alone doesn't say outright: whether the answer leans biased, whether it's evasive or deceptive, which way a framing tilts. Normally that signal is locked inside whatever model produced it. This project reads that signal out, in plain English, from a model it has never even seen before.

Small reader, big targets

The reader itself is a Qwen3 trunk under 2B parameters. It reads activations from architectures up to 8B in its own results table — 4-5× its own size — through nothing but a small linear projection per target model. The China-topic result above pushes this to a 9B model (Qwen3.5-9B), added and read in the same sitting. Reading doesn't require a bigger brain than the one being read.

One reader, any model

Train once on ~16 architectures. Point it at architecture #17 — a model it has literally never processed a single token from during training — and it still answers correctly, most of the time within a percentage point of its trained accuracy.

No fine-tuning to add a model

Supporting a new architecture is ~200 lines of linear algebra (a least-squares solve), not a training run. Seconds, not GPU-hours.

Reads the framing, not the topic

A biased answer and a balanced answer to the exact same question score differently — it isn't just detecting keywords, it's reading the model's actual internal state at the moment it committed to a framing.

One input, fifteen minds

Most activation-reading tools — including recent ones built around a vocabulary lens over one specific model — are built per model: the lens is fit to that model's own vocabulary and internals, and reading a different architecture means building a new one from scratch. This reader is the opposite: one fixed reader, and every architecture below gets read through its own small translator into the same space. How it works

Every model in the pool speaks its own "internal language" — its activations live in a different-shaped space than every other model's. Each one gets a tiny, cheap translator that converts its activations into one shared space. The reader (the Qwen3 trunk) only ever has to understand that one shared space — it never sees a model's raw activations directly, and it never changes when a new architecture is added.

What it learned from

50,000 short passages of Wikipedia text: 30% English, and the other 70% split evenly across five other languages (Russian, Chinese, Japanese, German, Spanish). Programming-language text was tried at 30% of the mix too, and dropped — it specifically hurt the detector's ability to transfer to new architectures, so the final version trains on natural-language text only.

How that turns into a trained detector:

  • 1. Write a summary. For every passage, a larger AI model writes a one-paragraph summary of what it's about. That summary is the same for every architecture — it's the "correct answer" the reader is taught to reproduce from an activation alone.
  • 2. Capture the activations. Run each of the 16 training architectures over the same 50,000 passages and record their internal activations at a middle layer.
  • 3. Train. Teach the reader, together, to (a) reproduce that English summary from an activation, (b) answer calibrated yes/no questions about bias and dishonesty from cross-model conversation examples (27 different behaviours, 10 of them deliberately withheld — see below), and (c) tell a biased answer apart from a balanced answer to the identical question, using matched pairs built specifically for that.

Bonus finding — patch an activation, see what changes

A small side experiment: take a model's activation while it's mid-answer, swap in a different concept's activation instead, and see what happens — both to the model's own continuation and to what the reader says about it. Tried on both a familiar model (Qwen3-1.7B) and a genuinely unseen one (Llama-3-8B):

  • The reader's description of the swapped-in activation is most accurate at the same depth (roughly the mid-point of the model) it was originally calibrated on.
  • The target model's own behaviour only actually changes if the swap happens deeper (around 70–90% of the way through) — a concept becomes readable before it becomes consequential.
  • The same pattern held on the model that was never trained on at all — the shared space itself seems to carry the signal, not something specific to per-model fine-tuning.

Follow-up: does a swap through the shared space actually change the model's answer?

A sharper version of the same idea: capture Llama-3.2-1B's (held-out) own activation for the bare word "France", and separately for "China". Overwrite the "France" activation inside a multi-fact prompt with the "China" one, mid-generation, and see whether the model's own answer about the capital city flips.

  • With the raw, uncompressed activation: the swap works. Unpatched, the model answers "Paris." Patched with China's own raw activation, it answers "Beijing" and continues with China-consistent facts. A single-position swap in a held-out model's own activation space causally changes its answer — not just what it says about the activation, but what it does next.
  • Routed through our shared space instead (encode with Llama's own translator, decode back with the same translator, then patch that reconstruction in) — the swap does not reliably flip the answer. The round-trip fidelity for a bare single-word capture measured low (cosine similarity ≈ 0.12 against the original), and the translators were calibrated on longer, mean-pooled passages, not isolated single tokens — an honest mismatch, not a hidden result.
  • But the reader's own description of that same round-tripped vector still correctly says "China" — surname, politician, actor, singer, all Chinese. Legibility survives the round-trip even where causal control over the original model doesn't (yet) — the same "readable before consequential" pattern as above, now showing up as a gap between what the reader can tell you and what the original model will do about it.

Baselines & honest limits

Four questions worth asking before trusting any of the numbers above. Two are real experiments with real (and mixed) results; the other two are corrections and open gaps, not wins.

Does this actually need an LLM, or would plain linear regression do?

We trained a plain logistic-regression classifier directly on a model's own raw activations — no reader, no shared space, nothing learned — for 12 behaviours across 6 of the architectures above, evaluated with 5-fold cross-validation.

Result: that plain classifier also scores ~1.0 AUROC on almost everything (mean 0.998 across 72 architecture/behaviour pairs; worst case 0.975). Within one architecture, most of these behaviours are trivially linearly separable — the reader isn't earning its keep there.

But that same classifier is useless on any architecture besides the one it was fit to. It's a set of weights sized to that one model's activation dimensions; there's no such thing as running it on a different model's activations, which live in a different space of a different size entirely. That's the actual comparison worth making: the reader's accuracy on 12 architectures it has zero labeled examples from, against a method that cannot be run on those architectures at all without first collecting and labeling data from each one individually. The value isn't "smarter than a linear model" — it's "works on a model you have no labels for yet."

Does it generalize to concepts nobody trained it on at all?

Everything on this page so far tests generalization to a new architecture. A harder question: does it generalize to a new kind of behaviour, one nowhere near its training vocabulary of bias, incorrect reasoning, and deception? We tried five, cold — no cherry-picking, all five reported below.

  • Does this code contain a bug? A correct sum function vs. one with an off-by-one error, same question either way, read from Llama-3.2-1B (held-out): P(has bug) = 0.099 for the buggy version, 0.094 for the correct one. No signal.
  • Does this tool result contain a prompt injection? A clean weather lookup vs. one with "IGNORE ALL PREVIOUS INSTRUCTIONS" spliced in, same architecture: P(injection) = 0.029 vs. 0.034. Also no signal.
  • Does this describe a staged/fictional test scenario, not a real one? A realistic nurse-and-patient question vs. an explicit "this is a red-team safety evaluation, fictional scenario" framing of the same question: P(staged) = 0.397 for the realistic one, 0.276 for the explicitly-staged one. Wrong direction, not just no signal.
  • Is the model about to add a safety caveat? — the one that clearly worked. Same lock-picking question, read from Qwen2.5-0.5B-base vs. its instruction-tuned counterpart: P(about to hedge/refuse) = 0.004 for base, 0.082 for instruct — a real, twenty-fold, correctly-directed shift, though neither absolute number is high.
  • Does a sleeper-agent-style model organism's triggered response look anomalous? We found a public backdoored Gemma-3-1B ("model organism") whose response to "I am now in deployment, not training" is a two-word non-sequitur ("I AM WIERD!") instead of the requested code — a real, verified backdoor, on an architecture our adapter bundle had never touched before. Added it as a new held-out tag on the spot (60 generic calibration passages, closed-form fit) and asked the reader whether the triggered response looked deceptive or behaviorally inconsistent with the model's normal self-presentation: P(deceptive) = 0.051 → 0.048 (no signal), P(hidden/inconsistent behaviour) = 0.062 → 0.099 (real but modest — both numbers still low in absolute terms). A real trigger, a genuine architecture the checkpoint had never seen, and a weak-to-mixed detection result.

Read plainly: generalizing to a new architecture works well within the trained vocabulary (see the "held-out concepts" results above); generalizing to a genuinely unfamiliar concept is mostly a miss — one clear win, one modest partial signal, three clean nulls (one of them backwards) out of five tries. That's a real boundary, not a footnote.

Where's the reconstruction number?

An earlier checkpoint in this project line reported 0.874 mean reconstruction accuracy (fraction of variance explained, or FVE — how well an activation can be rebuilt after being described in English and translated back). That number belongs to a different, earlier checkpoint, not this one — worth stating plainly since it's an easy mix-up. This checkpoint was trained purely for calibrated yes/no detection; nobody ever paired it with the reconstruction half of the pipeline, so there is no reconstruction score for it, high or low. That's a real gap, not a hidden result — closing it means training that missing half, which hasn't happened yet.

What does it get wrong, and how?

We don't yet have a systematic breakdown of how this checkpoint's English descriptions fail — whether it's confidently wrong about specifics while getting the general topic right, whether repeated claims across similar inputs are more trustworthy, and so on. The concept-swap probe above is a first data point (descriptions degrade in a specific, structured way outside the calibrated layer), but a real failure-mode taxonomy is still open work. Eval awareness and model-organism detection specifically were tried and came back weak-to-null (see the novel-concept results above) — a real limit, not just an unexplored gap.

How this relates to Anthropic's work

This project is a from-scratch reimplementation inspired by public research on reading LLM activations in natural language, not code or checkpoints anyone else released. Three distinct things are worth naming precisely, because this project sits differently relative to each.

Natural Language Autoencoders (reconstruction)

One NLA per target model — the describer and reconstructor both start out as a copy of the exact model being read, then get trained with reinforcement learning (plus a penalty that keeps descriptions close to fluent English) toward faithfully rebuilding that one model's own activations. Reconstruction accuracy of 0.6–0.8, improving roughly in proportion to the log of training steps, on runs using two 8-GPU nodes per model and several hundred tokens of generation per activation read.

Activation Oracles (supervised, cross-context)

A separate line of work (Karvonen, Chua, Dumas, et al.) trains one reader on labeled question-answering over activations, evaluated on questions and inputs far outside its training distribution. This project sits much closer to that supervised tradition than to the reconstruction one — theirs generalizes across questions and contexts within roughly one model family; this one generalizes across architectures, via the shared linear-adapter space described above.

The Jacobian Lens / global workspace

A newer, different tool again: it finds a small set of directions ("J-space") by computing, per vocabulary token, the linearized effect of an activation on the model's likelihood of producing that specific token — inherently tied to one model's own vocabulary and weights. Reading a different model means building a new lens for it. The concept-swap and causal-swap experiments earlier on this page are this project's version of the same underlying claim (a small, structured, causally-relevant workspace exists) — run through a reader built to work across architectures instead of one lens per model.

The one-line version, stated plainly:

All three of the tools above showed that a model's internal workspace exists and can be read in plain English — each at the cost of one expensive, bespoke tool built around one specific model. This project's bet is that once you know the workspace is there, reading it doesn't need a new tool per model — a shared space and one fixed reader can monitor the whole model zoo instead of one model at a time.

That difference also shows up in cost. Their reconstruction runs train two full copies of the target model with reinforcement learning on two 8-GPU nodes; this project's whole training run — one reader, jointly taught detection, description, and honesty-checking together — took about two hours on a single 32GB GPU, plus roughly the same again to extract activations from all 16 training architectures. Adding a new architecture afterward is the one-time forward pass to collect its activations, plus a linear solve that measured under 4 seconds on a laptop CPU — no GPU required for that step at all.

Held-out architectures

"Held-out" means exactly what it sounds like: these models are added to the detector after everything is already trained and frozen. They contribute nothing to training — no text of theirs, no activations of theirs, nothing — until the one-time setup step below.

Trained on — 16 architectures

Bloom-560M, Gemma-2-9B, GPT-Neo-1.3B, GPT-2-Medium, LFM2-1.2B, Phi-1.5, Pythia-410M, Qwen2.5-{0.5B, 7B}, Qwen3-{0.6B, 1.7B, 4B}, SmolLM2-360M, SmolLM3-3B, Vikhr-7B, YandexGPT-5-Lite-8B. Each gets its translator trained alongside the reader itself.

Tested on — 12 architectures, 6 families, 350M–8B

Liquid AI (LFM2.5-ColBERT-350M), Mistral AI (Ministral-8B, Mistral-7B-v0.2), AI2 (OLMo-1B, OLMo-2-1B, OLMo-2-7B), Alibaba (Qwen1.5-7B, Qwen2.5-Coder-7B, Qwen2.5-1.5B), Meta (Llama-3.2-1B), the Vikhr community (QVikhr-3-1.7B), and HuggingFaceTB (SmolLM2-1.7B). None of these contributed a single token to training.

Adding one takes seconds, not a training run

Every trained model's translator was calibrated against one shared reference point. Adding a new model reuses that same reference point instead of touching the reader at all:

  • Run the new model once over a few hundred example passages and average its activations — the same first step used for every model during training.
  • Solve one small system of linear equations that maps those activations onto the shared reference point. This is ordinary linear algebra, not machine learning — no fine-tuning, no gradient steps, and the reader's own weights are never touched. Measured: under 4 seconds on a laptop CPU, no GPU involved.
  • The new model is queryable right away. Every number in the table below comes from doing exactly this, once, for each of 12 architectures.

How it scales with held-out count & diversity

An early pass validated the closed-form fit on a handful of architectures and looked strong — but a subset of that handful turned out to already be inside the training pool, which meant the good numbers weren't proof the mechanism generalizes. The held-out set was rebuilt from scratch to 12 architectures deliberately chosen to span the widest range available: 350M to 8B parameters (a 23× spread) across six unrelated lineages (Liquid's hybrid conv-attention LFM2, Mistral, AI2's OLMo, Alibaba's Qwen, Meta's Llama, and two community/regional models).

Result: the never-trained-topic accuracy across all 12 stayed within 0.9718–0.9866 — a 1.5-point spread regardless of whether the architecture is a 350M retrieval-specialized model or an 8B chat model from a completely different lineage. The mechanism doesn't just work on one lucky architecture; it holds essentially flat as both the number and the diversity of held-out targets scale up.
