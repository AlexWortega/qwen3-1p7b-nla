# v9 series — multilingual mix, LoRA capacity, ConvAdapter, Flamingo CA

Compact log of the v9.x experiment line. Each entry: motivation, training
recipe, evaluation, what we learned.

All variants share the same trunk (`Qwen3-1.7B`, `d_shared=2048`), the same
13 trained tags, and `anchor=qwen3-1p7b`. Differences are listed in **bold**.

## Pre-existing baseline: v8-mixed

- AV LoRA r=16 on Qwen3-1.7B, mean-pool + per-position mix, FineWeb-Edu 10k.
- Held-out FVE plateau ≈ 0.79; cos vs gold on Qwen2.5-7B = **0.609**;
  held-out cos plateau ≈ 0.59.
- On non-English input the AV collapses to canonical "Very Hungry Caterpillar"
  templates — the model speaks the activation but only in English.

## Corpus expansion: multilingual wiki (used by every v9 variant)

`scripts/scrape_wiki_hf.py` streams the `wikimedia/wikipedia` HF dataset and
takes 100 lead-section excerpts from each of `ru, zh, ja, ar, hi`. Result:
`activations_pool_multi/passages_multi.jsonl` (500 rows).

Teacher z is generated by Sonnet 4.6 via OpenRouter, which respects the
passage language (Russian → Russian z, Arabic → Arabic z). Cost ≈ $0.5.

`scripts/build_v9_combined_pool.py` merges the FineWeb 10k pool with the
multilingual 500 into `activations_pool_v9` (passages.jsonl is one
concatenated file with multilingual rows renumbered to `[10000, 10500)`).
Per-tag mean-pool shards are concatenated to match.

## v9 — multilingual mix, **LoRA r=16**, LinearAdapter

- Recipe: identical to v8-mixed but with the combined corpus, 1 epoch.
- Held-out tags added via `ModelPoolAdapters.add_held_out_tag()` after SFT.
- Eval (n=100, cos vs gold via `all-MiniLM-L6-v2`):

| split                | mean cos | note |
| -                    | -        | -    |
| trained FineWeb      | 0.521    | −9pp vs v8 baseline |
| held-out FineWeb     | 0.470    | −12pp vs v8 |
| multilingual (qwen3-4b) | 0.655 | Caterpillar collapse fixed; AV now emits Russian, Arabic, etc. |

Verdict: multilingual works (AV speaks the activation's native language) but
English plateau regressed. LoRA r=16 capacity bottleneck.

## v9.1 — same mix, **LoRA r=512**

Hypothesis: more capacity = enough room for both English and multilingual.

- LoRA r=512, α=1024, lr_av 1e-5, grad-checkpoint, 1 epoch (~3 h on 3×V100).

| split                | v9 r=16 | **v9.1 r=512** | Δ |
| -                    | -       | -              | - |
| trained FineWeb      | 0.521   | **0.546**      | +2.5pp |
| held-out FineWeb     | 0.470   | 0.461          | −1pp |
| multilingual         | 0.655   | **0.739**      | +8pp |

Verdict: r=512 helps multilingual hard, English trained a bit, **held-out
slightly worse** (richer SFT-mean target → lstsq held-out fit is less
transferable). Trade-off remains: multilingual ↑ but English plateau still
−6pp below v8.

## v9.2 — **ConvAdapter**, LoRA r=16

Hypothesis: replace plain Linear enc/dec with Linear + a small Conv1d over
the d_out axis (kernel=7, identity init). Adds local cross-channel mixing on
top of the lstsq warm-start; init forward is bit-identical to LinearAdapter.

Implementation:
- `nla.enc_dec_adapters.ConvAdapter` extends `LinearAdapter`.
- `ModelPoolAdapters` records `adapter_class` + `adapter_kwargs` in meta.json
  and instantiates the right subclass on load.
- `add_held_out_tag` wraps the fresh lstsq Linear via `ConvAdapter.from_linear`
  when the bundle is ConvAdapter (else state_dict shapes mismatch).
- `scripts/init_conv_adapters.py` re-keys an existing LinearAdapter bundle.
- Trained with the same `train_av_multi.py` recipe as v9.

| split                | v9 r=16 | v9.1 r=512 | **v9.2 conv** |
| -                    | -       | -          | -             |
| trained FineWeb      | 0.521   | 0.546      | 0.524         |
| held-out FineWeb     | 0.470   | 0.461      | **0.492** ⭐ |
| multilingual         | 0.655   | 0.739      | 0.696         |

Verdict: **best held-out of any v9 variant** (+2.2pp over v9 r=16, +3.1pp
over v9.1 r=512). Multilingual sits between v9 and v9.1. Trained flat vs v9.
For the add-tag flow (where held-out generalisation matters most), this is
the strongest checkpoint so far.

Published as `AlexWortega/Qwen1.7bnla/adapter_universal_v9_2_conv` on HF.

## v9.3 — **Flamingo-style cross-attention injection** (running)

Hypothesis: instead of swapping the `㈎` embedding for `enc_M(h)`, treat
`enc_M(h)` as a KV source consulted via gated cross-attention at the AV's
mid layer. Closer to multimodal LLM injection.

Implementation:
- `nla/flamingo.py`:
  - `FlamingoInject` — multi-head cross-attention with `tanh(gate)` residual,
    `gate=0` at init so the wrapped AV is bit-identical to the un-wrapped one.
  - `FlamingoWrappedLayer` — wraps a decoder layer; runs the original layer
    then `FlamingoInject(hidden, model._flamingo_kv)`. Forwards unknown
    attribute lookups to the original layer (needed for Qwen3's
    `attention_type`).
  - `set_flamingo_kv` — context manager that sets `av._flamingo_kv` for the
    duration of a forward call.
  - `attach_flamingo(av, layer_idx, ca)` — swap one decoder layer for the
    wrapped version.
- `scripts/train_av_flamingo.py` — fork of `train_av_multi.py` that builds
  a `FlamingoInject` at the chosen mid layer (default L14), trains AV LoRA
  + Flamingo CA + enc/dec adapters jointly. Param groups deduplicated by
  id so the Flamingo params (children of the AV tree) don't appear twice.
- The `㈎` marker stays in the prompt; the AV's embedding for it isn't
  overwritten — the only injection path is the CA.

Initial gate is 0, so step 0 reproduces the un-wrapped AV's behaviour. By
the first few hundred steps the gate drifts a small amount (−0.01 to −0.02).

Status: training (~5–7 h on 3×V100). Eval will mirror v9 / v9.1 / v9.2
splits. Hypothesis to test:
- If multilingual ≥ v9.1's 0.739 with held-out ≥ v9.2's 0.492 → Flamingo is
  the new mainline.
- If both worse → fall back to v9.2 conv as the production checkpoint and
  explore other recipes (corpus rebalancing, two-stage SFT).

## v10 (queued) — extend v8 with Soyuz-sft coding domain

`AlexWortega/Soyuz-sft` is the coding/agent-trace SFT mix. Even though it's
not multilingual, it covers a domain v8 / v9 have zero exposure to (SWE-bench
trajectories, agent tool-use). 500 resolved traces sampled into
`activations_pool_soyuz/passages.jsonl` with `text` = concatenated chat
trace and `z` = first user message (the PR description). No OpenRouter
call — z is intrinsic to the dataset.

`scripts/build_soyuz_corpus.py` is the corpus builder.
`scripts/train_av_multi.py` gained `--resume-av-dir` so we can continue from
the v8 checkpoint instead of training from scratch.

Plan (when GPUs free up after v9.3 finishes):
1. Extract mean-pool activations on the Soyuz corpus for the 13 trained tags.
2. `python scripts/train_av_multi.py --resume-av-dir <v8 av>`, 1 epoch,
   low LR (5e-6) so the v8 English+multilingual plateau isn't disturbed.
3. Eval on Soyuz held-out (coding) + FineWeb (regression check) +
   multilingual.

## Take-aways

- **Pareto is hard**: every v9 variant trades English plateau for multilingual
  ability. The corpus mix ratio (500 multilingual / 10500 total = 4.7%) is the
  primary driver; LoRA rank and adapter arch are second-order.
- **Conv on the adapter > more LoRA rank** for held-out transfer. Identity-init
  Conv1d post-projection preserves the lstsq warm-start exactly and lets the
  bundle improve under SFT without disturbing the lstsq target distribution
  used by `add_held_out_tag`.
- **Flamingo is being tested** as an arch question, not a corpus question.
  Whether or not it wins, it disambiguates "embedding-swap is the bottleneck"
  from "the corpus mix is the bottleneck".
- **OpenRouter budget cap on 2026-05-29** ruled out new teacher z calls;
  v10 sidesteps that by extracting z from the dataset's own user messages.
